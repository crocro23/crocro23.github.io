# 🚀 Méthodes d’agilité

Les méthodes agiles permettent de développer des produits de manière **itérative**, **collaborative** et **orientée valeur**.

## 📚 Principales approches

| Méthode | Objectif principal | Points clés |
|---|---|---|
| 🗂️ **Kanban** | Visualiser et fluidifier le travail | Flux continu, amélioration continue |
| 🏃‍♂️ **Scrum** | Organiser le travail en sprints | Rôles, cérémonies, incréments |
| 💻 **XP** | Améliorer la qualité logicielle | TDD, pair programming, CI/CD |
| 🏢 **SAFe** | Étendre l’agilité à grande échelle | Coordination multi‑équipes |

---

# 🏭 Kanban & Lean

Kanban est issu du **Lean Management**.

## 🔑 Principes Lean

### 🧹 Méthode des 5S

1. 🗑️ **Supprimer l’inutile**
2. 📦 **Situer / ranger**
3. 🧹 **Scintiller / nettoyer**
4. 📏 **Standardiser**
5. 🔄 **Suivre / pérenniser**

## 📌 Concepts importants

- 👀 Rendre l’avancement visuel
- ⚙️ Standardiser les processus
- 🗺️ Cartographier les flux de valeur (*Value Stream Map*)
- 🔧 Favoriser le **Kaizen** (amélioration continue)

---

# 🏃‍♂️ Scrum

Scrum est un **cadre léger** basé sur l’empirisme.

## 🧱 Les 3 piliers

- 🔍 Transparence
- 👁️ Inspection
- 🔄 Adaptation

## 💎 Les 5 valeurs Scrum

- 🤝 Engagement
- 💪 Courage
- 🎯 Focus
- 🌐 Ouverture
- 🙏 Respect

## 👥 Les 3 rôles

| Rôle | Responsabilité |
|---|---|
| 📋 Product Owner | Définit les priorités et maximise la valeur |
| 🎩 Scrum Master | Garant du cadre Scrum |
| 👨‍💻 Développeurs | Réalisent l’incrément produit |

## 📅 Les 5 événements

1. 🏃 Sprint
2. 📅 Planification
3. 📞 Daily Scrum
4. 👓 Revue
5. 🔙 Rétrospective

## 📦 Les 3 artefacts

- 📦 Backlog Produit
- 🏃‍♂️ Backlog Sprint
- ➕ Incrément

> 🎯 Objectif : livrer régulièrement de la valeur et améliorer continuellement l’équipe.

---

# 📘 Scrum Expansion Guide

Le Scrum Expansion Guide :

- 🔬 Approfondit l’empirisme
- 🧩 Clarifie les rôles et artefacts
- 🔄 Encourage les pratiques complémentaires (*refinement*, amélioration continue…)

---

# 💻 eXtreme Programming (XP)

XP met fortement l’accent sur la **qualité logicielle** et le **feedback rapide**.

## 💎 Valeurs XP

- 🗣️ Communication
- 🧩 Simplicité
- 🔄 Feedback
- 💪 Courage
- 🙏 Respect

## 🛠️ Pratiques XP

- ✅ TDD (*Test Driven Development*)
- 🔗 Intégration continue
- 👥 Pair programming
- ⏳ Itérations courtes (1 à 2 semaines)
- 🤝 Collaboration étroite avec le client

---

# 🏢 SAFe

SAFe (*Scaled Agile Framework*) permet d’étendre l’agilité à l’échelle de l’entreprise.

## 🔑 Fondements

- 🛠️ Lean
- 🔄 DevOps
- 🏃 Scrum

## 💎 Valeurs SAFe

- 🎯 Alignement
- ✅ Qualité intégrée
- 🔍 Transparence
- 🔧 Amélioration continue

## 🚂 Organisation

- Mise en place d’**Agile Release Trains (ART)**

---

# 🚫 Limites du cycle en V / cascade

## ⚠️ Problèmes fréquents

- ⏰ Feedback trop tardif
- 📆 Plusieurs mois avant une livraison

## ✅ Avec des livraisons régulières

- ⚡ Connaître sa vélocité
- 🤖 Automatiser build, tests et déploiement
- 🧪 Améliorer conception et tests unitaires

---

# 💬 Importance du feedback utilisateur

Un échange verbal permet de :

- 👏 Montrer le travail accompli
- 🔍 Comprendre l’usage réel
- ⚠️ Identifier les difficultés
- 💡 Donner du sens au travail

---

# ❌ Causes d’échec d’un projet agile

## 🛑 Causes techniques et organisationnelles

- 🛠️ Manque de compétences techniques
- 🚷 Non‑adhésion aux valeurs agiles
- 🔧 Absence de TDD, CI ou refactoring
- 🐞 Mauvaise collaboration (Jira, Git, Jenkins, Docker…)
- 🧱 Architecture non modulaire
- 😴 Rétrospectives peu engageantes
- 📉 Peu de feedback client

---

# 📊 Mesurer les avancées

## 📌 Indicateurs utiles

- 🌟 Chaque projet est unique
- ⚡ La vélocité correspond à la moyenne des itérations précédentes
- 🔥 Le burndown représente le travail restant
- ✅ Les tests automatiques de recette mesurent le taux de progression

---

# ⚙️ Fonctionnement du Scrum

## 🧩 Principes clés

- Résoudre des problèmes complexes pas à pas
- 🤝 Instaurer la confiance
- 🧠 Favoriser l’introspection
- 🏆 Rechercher l’excellence technique

---

# 👥 Les rôles Scrum

## 🎩 Scrum Master

### Missions

- ⚖️ Garant du cadre Scrum
- 🎭 Animateur empathique et rigoureux
- 🧗‍♂️ Aide l’équipe à surmonter les obstacles

## 📋 Product Owner

### Missions

- 📌 Définit les priorités
- 📝 Rédige les cas d’usage et scénarios de tests
- ✅ Valide les livrables
- 🌟 Porte la vision produit

## 👨‍💻 Développeur

### Missions

- 💻 Développement, UX ou tests
- 🌟 Recherche d’autonomie et de qualité

---

# 🏃‍♂️ Sprint

Un sprint contient :

- 🎯 Un objectif clair
- 📋 Des cas d’usage définis
- ✂️ Un découpage du travail

---

# 📞 Daily Scrum

## ❓ Questions classiques

1. ✅ Qu’ai‑je fait ?
2. 🛠️ Sur quoi vais‑je travailler ?
3. ❓ De quoi ai‑je besoin ?

---

# 👓 Revue de sprint

Objectifs :

- 🚀 Décider d’une mise en production
- 💬 Recueillir du feedback élargi

---

# 🔙 Rétrospective

## 🔎 Analyse de sprint

- 📅 Frise chronologique
- 👍 Ce qui a fonctionné
- 👎 Ce qui n’a pas fonctionné
- 📈 Actions réalistes et mesurables

---

# 💻 Découvrir XP

## ⚠️ Problèmes typiques

- ⏳ Délais non tenus
- ➕ Difficulté à ajouter des fonctionnalités
- 🐞 Trop de bugs
- ❓ Mauvaise compréhension fonctionnelle

## 👥 Actions XP

- 🤝 Pair programming
- 🔗 CI/CD
- ✅ TDD
- ✂️ Découpage des tâches
- 📦 Livraisons périodiques
- 🐞 Correction rapide des bugs

---

# 💪 Valeurs XP

- 💪 Courage
- 🗣️ Communication
- 🔄 Feedback
- 🧩 Simplicité

# ⏳ Temporalité du feedback

| Niveau | Temps de retour |
|---|---|
| 👥 Pair programming | ⚡ Immédiat |
| ✅ Tests unitaires | ⏱️ Secondes |
| 🔗 CI/CD | ⏲️ Minutes |
| 📝 Recette | 🕰️ Heures |
| 👥 Clients | 📅 Jours |
| 🔄 Itérations | 📆 Semaines |

# 👥 Rôles XP

| Rôle | Responsabilité |
|---|---|
| 👨‍🏫 Coach XP | Encourage les tests et les bonnes pratiques |
| 📊 Tracker | Suit les métriques et le planning |

| 👥 Utilisateur | Collabore avec les développeurs |

# 🔄 Gestion du changement

## 📌 Principes importants

- 💸 Plus un changement arrive tard, plus il peut coûter cher
- ⚠️ Le problème vient des conséquences, pas du changement lui‑même
- 👨‍💻 Tout le monde est responsable du code

## 📏 Règles communes

- Indentation
- Nommage
- Organisation des classes et fonctions
- Tests

## 👥 Pair programming

- 👨‍✈️ Pilote
- 🧭 Copilote

## ✅ Qualité logicielle

- Tests automatisés obligatoires
- 🔄 TDD :
  1. ❌ Le test échoue
  2. ✅ Le test passe
  3. 🔧 Refactoring

> 🚫 Pas de refactoring sans tests.

## 📜 Tests de recette

Les scénarios clients deviennent des tests de recette (*Gherkin*).
